### 2. Модернизация Markdown редактора

**Действие пользователя:**
```
Исправить markdown:
1. Не корректно отображаются одинарные переносы строк
2. В нем не весь функционал
3. Нужно сделать не только включение какой-то пометки текста, но и снятие её (toggle функциональность)
```

**План модернизации:**
1. Исправить одинарные переносы строк (nl2br)
2. Добавить toggle для inline форматирования (bold, italic, code)
3. Добавить toggle для line prefixes (headings, lists, quotes)
4. Добавить toggle для code blocks

**Выполненные действия:**

#### Шаг 1: Исправление переносов строк
- `markdown_utils.py`: Добавлено расширение `markdown.extensions.nl2br` для обработки одинарных переносов строк
- Результат: ✅ Одинарные переносы строк теперь отображаются как `<br>`

#### Шаг 2: Toggle для inline форматирования
- `templates/task_detail.html`: 
  - Добавлена функция `toggleInline()` для переключения bold, italic, inline code
  - Обновлены кнопки панели инструментов для использования `toggleInline`
- Результат: ✅ Bold, italic, inline code работают с toggle функциональностью

#### Шаг 3: Toggle для line prefixes
- `templates/task_detail.html`:
  - Добавлена функция `toggleLinePrefix()` для переключения заголовков, списков, цитат
  - Обновлены кнопки H2, списков, цитат
  - Исправлена логика обработки границ строк
- Результат: ✅ Заголовки, списки, цитаты работают с toggle функциональностью

#### Шаг 4: Toggle для code blocks
- `templates/task_detail.html`:
  - Добавлена функция `toggleFence()` для переключения блоков кода
  - Добавлена кнопка для блоков кода `{ }`
- Результат: ✅ Блоки кода работают с toggle функциональностью

**Проблемы и решения:**
- Проблема: Кнопки панели Markdown "деактивировали" текстовое поле
- Решение: Добавлен `textarea.focus()` перед чтением selection, возврат `false` из обработчиков
- Проблема: `toggleLinePrefix` добавлял префиксы в неправильных местах
- Решение: Исправлена логика определения границ строк и применения префиксов

на основе дат выполнения/отложенности.

- Создан детальный план в `docs/technical/AUTO_CATEGORY_MIGRATION_PLAN.md`
- Определены правила категоризации по датам
- Определены правила перемещения задач

**Выполненные действия:**

#### Этап 1: Создание модуля миграции
- `category_migration_manager.py`: Создан модуль с полной логикой:
  - `get_category_by_date()` - определение категории по дате
  - `is_overdue()` - проверка просроченности
  - `should_migrate_task()` - проверка возможности перемещения
  - `migrate_tasks()` - выполнение миграции
  - `start_scheduler()` / `stop_scheduler()` - управление планировщиком
  - Планировщик с настраиваемым интервалом (30 минут по умолчанию)

#### Этап 2: Обновление конфигурации
- `config_manager.py`: 
  - Добавлена поддержка секции `auto_migration`
  - Обновлены смайлики категорий в конфигурации по умолчанию
  - Добавлен метод `get_auto_migration_config()`
- `config.json`: 
  - Обновлены смайлики: 📝 Новые, 📅 Завтра, 👁️ Отслеживаем, 🔥 Сегодня, 📆 На неделе, 🔮 Далекие
  - Добавлена секция `auto_migration` с интервалом 30 минут

#### Этап 3: Интеграция
- `tray_app.py`: 
  - Импорт и запуск менеджера миграции при старте
  - Остановка менеджера при выходе из приложения
- `app.py`: 
  - Запуск менеджера миграции при прямом запуске Flask

#### Этап 4: Тестирование
- Создан и выполнен тестовый скрипт для проверки логики:
  - ✅ Парсинг дат (6 тестов) - все пройдены
  - ✅ Определение категорий (10 тестов) - все пройдены
  - ✅ Правила перемещения (10 тестов) - все пройдены
- Протестирован таймер с коротким интервалом - работает корректно
- Исправлена ошибка парсинга datetime (порядок проверок)
- Улучшена обработка пустых строк в датах

**Логика определения категорий:**
- "Сегодня" (working): дата = сегодня или просрочена
- "Завтра" (later): дата = завтра
- "На неделе" (waiting): дата в текущей неделе (если пятница, то + понедельник)
- "Далекие" (think): дата > вторник следующей недели

**Правила перемещения:**
- Перемещать из: "Новые", "Далекие", "На неделе", "Завтра"
- НЕ перемещать из: "Отслеживаем", "Сегодня" (кроме просроченных)
- Просроченные задачи → всегда в "Сегодня"

**Результат:** ✅ Система автоматического перемещения задач реализована и протестирована

- Реализовано контекстное меню для выбора значения под плашкой

- `POST /api/update_priority` — обновление приоритета задачи (`low|medium|high`)
