# 📝 ToDoLite - Профессиональный Задачник

[![Version](https://img.shields.io/badge/version-1.6.1-dev-blue.svg)](https://github.com/kabzon93region/ToDoLite/releases)
[![License](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)
[![Python](https://img.shields.io/badge/python-3.8+-blue.svg)](https://python.org)
[![Platform](https://img.shields.io/badge/platform-Windows-lightgrey.svg)](https://github.com/kabzon93region/ToDoLite)

Профессиональный задачник на Python с веб-интерфейсом, который отлично работает даже на старом оборудовании. Поддерживает два режима отображения: матрицу Эйзенхауэра и канбан-доску.

> **🚀 v1.6.1 Development** - Версия в разработке

## ✨ Особенности

- 🚀 **Легкий и быстрый** — Flask, SQLite и минимальный набор библиотек (см. таблицу зависимостей ниже)
- 💾 **Локальное хранение** - все данные хранятся в файле базы данных
- 📱 **Адаптивный дизайн** - работает на любых устройствах
- 🎨 **Темный интерфейс** - современный дизайн в стиле Cursor AI IDE
- 🔄 **Три режима отображения**:
  - **Agile доска**: Новое, К размышлению, Позже, Ожидание, В работе, Отслеживаем, Готово, Отменено
  - **Матрица Эйзенхауэра**: Важное & Срочное, Важное & Не срочное, Не важное & Срочное, Не важное & Не срочное
  - **📦 Архив**: Архивированные задачи с возможностью восстановления
- ⭐ **Приоритеты**: Низкий, Средний, Высокий
- 🏷️ **Система тегов** - организация задач с помощью хештегов
- 🔍 **Фильтрация** - по статусу, приоритету, матрице Эйзенхауэра и тегам
- 🖱️ **Drag & Drop** - перетаскивание задач между категориями
- 💬 **Комментарии** - добавление комментариев к задачам
- 🖥️ **Поддержка трея** - работа в фоне с иконкой в системном трее
- ⚙️ **Настройка** - конфигурируемые названия категорий и их порядок
- 📅 **Подсветка дат** - цветовая индикация срочности задач

## 🛠️ Установка и запуск

### Требования
- Python 3.8 или выше
- Windows 10/11 (64-bit)
- 4 ГБ RAM (минимум)
- 100 МБ свободного места

### 🚀 Быстрый старт (для клиентов)

1. **Скачайте клиентский архив** `ToDoLite_v1.5.5.zip` (или актуальный из [релизов](docs/releases/)). В архиве файлы лежат **в корне** (без вложенной папки): код, `README.md`, `LICENSE`, `CLIENT_README.md`, `install.bat`, `run_tray_silent.bat`, `start.bat`, `convert_line_endings.*` и т.д. Виртуальное окружение в архив **не входит** — его создаёт `install.bat`.

2. **Распакуйте** в любую папку (например, `C:\ToDoLite\`).

3. **Установите зависимости:**
   ```bash
   install.bat    # от имени администратора: создаёт ToDoLite_venv и pip install
   ```

4. **Запустите:**
   ```bash
   start.bat                 # обёртка над run_tray_silent.bat (в комплекте архива)
   ```
   Либо напрямую: `run_tray_silent.bat`.

5. **Браузер:** `http://localhost:5000`

### 🔧 Установка для разработчиков

1. **Настройте виртуальное окружение:**
   ```bash
   python -m venv ToDoLite_venv
   ToDoLite_venv\Scripts\activate
   ```

2. **Установите зависимости:**
   ```bash
   pip install -r requirements.txt
   ```

3. **Запустите приложение:**
   ```bash
   python tray_app.py
   ```

### 🔄 Обновление приложения

Сохраните `tasks.db` и при необходимости `config.json`, скачайте новый архив или обновите файлы из репозитория, затем снова выполните `install.bat` (или `pip install -r requirements.txt` в существующем venv).

### Альтернативный запуск (без виртуального окружения)

Если хотите установить зависимости глобально:

1. **Установите зависимости:**
   ```bash
   pip install -r requirements.txt
   ```

2. **Запустите приложение:**
   ```bash
   python app.py
   ```

## 🎯 Как использовать

### Основные функции

1. **Добавление задачи:**
   - Название и краткое описание (обязательно)
   - Форма в **четыре колонки**: теги, даты, статус, Эйзенхауэр, напоминание, треды и т.д.; подробное описание (Markdown) — блоком на всю ширину снизу
   - Поле **«Ответственный»** в форме создания временно скрыто (в БД передаётся пустое значение); при редактировании задачи поле по-прежнему доступно
   - Нажмите «Добавить задачу»

2. **Управление задачами:**
   - **Открыть задачу** - просмотр полной информации
   - **Перетащить** - изменить статус задачи перетаскиванием
   - **Готово** - быстро отметить задачу как выполненную
   - **📦 Архивировать** - архивировать выполненную/отмененную задачу
   - **Редактировать** - изменить параметры задачи
   - **Удалить** - удалить задачу (с подтверждением)

3. **Фильтрация задач:**
   - **По статусу** - отфильтровать по текущему статусу
   - **По приоритету** - отфильтровать по уровню важности
   - **По Эйзенхауэру** - отфильтровать по матрице важности/срочности
   - **По тегам** - отфильтровать по выбранным тегам

4. **Режимы отображения:**
   - **Agile доска** - группировка по статусу выполнения
   - **Матрица Эйзенхауэра** - группировка по важности и срочности
   - **📦 Архив** - просмотр архивированных задач

5. **📦 Система архивирования:**
   - **Архивирование** - выполненные и отмененные задачи можно архивировать
   - **Восстановление** - архивированные задачи можно вернуть в работу
   - **Защита архива** - редактирование архивированных задач заблокировано
   - **Статистика** - подсчет архивированных задач по статусам

6. **🔄 Автоматическая миграция задач:**
   - **Автоматическое перемещение** - задачи автоматически перемещаются между категориями на основе дат выполнения/отложенности
   - **Категории по датам:**
     - **🔥 Сегодня** - задачи на сегодня или просроченные
     - **📅 Завтра** - задачи на завтра
     - **📆 На неделе** - задачи в текущей неделе (если пятница, то + понедельник)
     - **🔮 Далекие** - задачи дальше чем вторник следующей недели
   - **Периодическая проверка** - автоматическая проверка каждые 30 минут (настраивается)
   - **Ручной запуск** - кнопка "🔄 Обновить" для немедленного обновления категорий
   - **Защита категорий** - задачи в "👁️ Отслеживаем" и "🔥 Сегодня" не перемещаются автоматически (кроме просроченных)

## 🔧 Настройка

### Конфигурация категорий
Создайте файл `config.json` в корне проекта для настройки названий и порядка категорий:

```json
{
  "statuses": {
    "new": "Новое",
    "to_think": "К размышлению", 
    "later": "Позже",
    "waiting": "Ожидание",
    "in_progress": "В работе",
    "tracking": "Отслеживаем",
    "done": "Готово",
    "cancelled": "Отменено"
  },
  "statuses_order": ["new", "to_think", "later", "waiting", "in_progress", "tracking", "done", "cancelled"],
  "eisenhower_labels": {
    "urgent-important": "Важное & Срочное",
    "urgent-not-important": "Не важное & Срочное",
    "not-urgent-important": "Важное & Не срочное", 
    "not-urgent-not-important": "Не важное & Не срочное"
  },
  "eisenhower_order": ["urgent-important", "urgent-not-important", "not-urgent-important", "not-urgent-not-important"]
}
```

### Изменение порта
Если порт 5000 занят, измените последнюю строку в `app.py`:
```python
app.run(debug=True, host='0.0.0.0', port=8080)  # Используйте любой свободный порт
```

### Доступ с других устройств
Приложение настроено для доступа с других устройств в локальной сети. Просто откройте в браузере:


## ⚠️ Известные проблемы

### Проблема с закрытием процессов при работе в трее
При использовании `run_tray_silent.bat` / трея могут оставаться процессы `pythonw.exe`.

**Решение:** запустите `kill_python_processes.cmd` или завершите процесс вручную. Для отладки можно запускать `python tray_app.py` из активированного venv — так проще видеть ошибки в консоли.

### Ложное «порт 5000 занят»
В `run_tray_silent.bat` проверка порта учитывает только состояние **LISTENING** и порт **5000** (не 50001 и т.п.), чтобы не блокировать запуск из‑за посторонних записей в `netstat`.

### Конвертация окончаний строк
При скачивании проекта с GitHub файлы могут иметь Unix-окончания строк (LF), что может вызвать проблемы в Windows.

**Решение:**
1. Запустите `convert_line_endings.cmd` для автоматической конвертации
2. Или используйте `python convert_line_endings.py` напрямую

**Причина:** Ограничения Windows в управлении дочерними процессами при работе через системный трей.
